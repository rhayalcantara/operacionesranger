**Fecha**: 2026-01-17
**Tarea padre**: T002
**Fase**: Fase 1A - Decisiones Arquitectónicas
**Estimación**: 4-5 horas

## Objetivo

Conectarse a la base de datos del sistema de RRHH existente (`db_aae4a2_ranger`) e investigar exhaustivamente la estructura de la tabla de empleados (`rh_empleado`) para validar que contiene los campos necesarios para la integración con el sistema de turnos. Documentar todos los hallazgos, crear queries reutilizables, e identificar gaps o workarounds necesarios.

## Contexto

El sistema de gestión de turnos necesita integrarse con el sistema de RRHH existente para:
- Obtener información de empleados (guardianes de seguridad)
- Validar que empleados activos existan antes de crear turnos
- Generar reportes con datos completos de empleados

**Información conocida**:
- Base de datos: `db_aae4a2_ranger`
- Tabla: `rh_empleado`
- Filtro de guardianes: `id_puesto = 97` (VIGILANTE DE SEGURIDAD)
- Conexión: Host localhost, User root, Password RHoss.1234

**Campos mínimos requeridos** (según CLAUDE.md):
- `id_empleado` o `id` - Primary key
- `cedula_empleado` o `cedula` - Nacional ID
- `nombres` + `apellidos` o `nombre_completo` - Employee name
- `status` o `activo` - Active status (1=active, 0=inactive)
- `id_puesto` - Job position ID (97 = VIGILANTE DE SEGURIDAD)
