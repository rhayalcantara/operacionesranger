- **Herramienta**: Bash con comando MySQL
- **Resultado esperado**: Procedimiento retorna correctamente es_feriado, feriado_id, tipo_feriado

### 4. Validar sp_determinar_tipo_turno
- **Descripción**: Probar determinación de tipo de turno según hora de entrada
- **Casos de prueba mínimos**:
  - Hora claramente diurna (ej: 08:00:00)
  - Hora claramente nocturna (ej: 20:00:00)
  - Hora límite inicio DIURNO (06:00:00)
  - Hora límite inicio NOCTURNO (18:00:00)
  - Hora edge (ej: 05:59:59 debería ser NOCTURNO)
- **Herramienta**: Bash con comando MySQL
- **Resultado esperado**: Procedimiento retorna DIURNO o NOCTURNO correctamente

### 5. Validar sp_registrar_turno
- **Descripción**: Probar registro de turnos con validaciones automáticas
- **Casos de prueba mínimos**:

  - Turno nocturno con horas extras (caso exitoso)
  - Turno en feriado (debe detectar automáticamente)
  - Turno duplicado (debe FALLAR con mensaje de error)
  - Turno con horas inválidas (debe FALLAR si excede límites trigger)
- **Consideraciones**: Requiere empleado_id válido de tabla RRHH (usar ID ficticio para pruebas)
- **Herramienta**: Bash con comando MySQL
- **Resultado esperado**:
  - Casos exitosos retornan turno_id y mensaje de éxito
  - Casos de error retornan NULL y mensaje descriptivo

### 6. Validar sp_generar_reporte_nomina

- **Herramienta**: Bash con comando MySQL
- **Resultado esperado**: Reporte con formato correcto, incluye columnas esperadas

### 7. Validar trigger trg_turnos_before_insert
- **Descripción**: Intentar insertar turnos que violen las validaciones
- **Casos de prueba (todos deben FALLAR)**:

- **Herramienta**: Bash con comando MySQL
- **Resultado esperado**:
  - Inserts inválidos rechazan con error SQLSTATE 45000
  - Insert válido (16h total dentro de límite) se acepta

## Riesgos y Consideraciones

### Riesgo 1: Falta de empleado_id válido
- **Descripción**: La tabla `turnos` requiere `empleado_id` que debe existir en `db_aae4a2_ranger.rh_empleado`
- **Mitigación**: Usar ID ficticio (ej: 1, 999) para pruebas. Documentar que es ID de prueba.

### Riesgo 2: No hay tabla rh_empleado accesible en entorno local
- **Descripción**: La tabla de empleados está en otra BD que puede no estar disponible
- **Mitigación**: Para pruebas usar IDs ficticios, documentar que la validación de FK se hará en integración

### Riesgo 3: Trigger puede impedir pruebas de validación
- **Descripción**: Si trigger funciona bien, bloqueará inserts inválidos (comportamiento esperado)
- **Mitigación**: Capturar errores SQL y documentarlos como éxito de validación

### Riesgo 4: Duplicados por ejecuciones previas
- **Descripción**: Si los scripts se ejecutan múltiples veces pueden fallar por duplicados
- **Mitigación**: Usar DELETE/TRUNCATE antes de insertar, o usar fechas diferentes en cada ejecución
