## Objetivo

Definir y documentar la estrategia de autenticación y autorización para el Sistema de Gestión de Turnos OperacionesRanger mediante un Architecture Decision Record (ADR). Aunque la implementación se realizará en Fase 2, es necesario tomar esta decisión ahora para preparar la arquitectura correctamente.

## Contexto

### Contexto del Proyecto

El Sistema de Gestión de Turnos es una aplicación backend (Node.js + TypeScript + Express.js) con frontend Angular que permitirá a supervisores registrar turnos de guardianes de seguridad y generar reportes quincenales para nómina.

**Usuarios del sistema**:
- **Administradores**: Gestión completa del sistema, configuración, usuarios
- **Supervisores**: Registro de turnos, gestión de guardias, generación de reportes
- **Consulta**: Visualización de reportes y turnos (solo lectura)

**Características del entorno**:
- Sistema interno de Guardianes Ranger (República Dominicana)
- No requiere integración con sistemas externos de autenticación
- Base de usuarios pequeña/media (~10-50 usuarios concurrentes)
- Frontend Angular separado del backend (SPA)
- API RESTful stateless

**Seguridad requerida**:
- Protección de datos de empleados (tabla RRHH con información personal)
- Control de acceso por roles (RBAC)
- Auditoría de operaciones críticas
- Expiración de sesiones por inactividad

## Notas Adicionales

### Referencia de ADR Format

Un buen ADR debe incluir:
1. **Title**: Breve y descriptivo
2. **Status**: Proposed, Accepted, Deprecated, Superseded
3. **Context**: Qué problema estamos resolviendo
4. **Decision**: Qué hemos decidido hacer
5. **Consequences**: Qué resulta de esta decisión (bueno y malo)

### Estándar de la Industria

Para APIs REST con frontend SPA, JWT es la opción más común porque:
- Stateless (escala horizontalmente)
- Funciona bien con CORS
- Soportado nativamente por Angular
- Librerías maduras en Node.js (jsonwebtoken, passport-jwt)
