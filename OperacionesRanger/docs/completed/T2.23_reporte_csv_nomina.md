## Formato CSV Generado

### Estructura

```csv
fecha,empleado_id,puesto_codigo,horas_normales,horas_extras,tipo_turno,es_feriado,tipo_feriado,incentivo
2026-01-02,1001,P001,10.00,2.00,DIURNO,NO,N/A,120.00
2026-01-03,1001,P001,10.00,0.00,NOCTURNO,NO,N/A,100.00
2026-01-21,1002,P002,8.00,2.00,DIURNO,SI,NACIONAL,0.00
```

### Características del CSV

| Característica | Valor | Verificación |
|----------------|-------|--------------|
| **Encoding** | UTF-8 con BOM | `\uFEFF` al inicio |
| **Separador** | Coma (`,`) | Standard CSV |
| **Line ending** | LF (`\n`) | Unix style |
| **Decimales** | 2 posiciones | `10.00`, `2.00` |
| **Booleanos** | "SI" o "NO" | No true/false |
| **Valores null** | "N/A" o "0.00" | Según campo |
| **Headers** | Incluidos | Primera línea |
| **Escape** | Comillas si necesario | Para valores con comas |

### Columnas del CSV

1. **fecha**: Fecha del turno (YYYY-MM-DD)
2. **empleado_id**: ID del empleado en BD RRHH
3. **puesto_codigo**: Código del puesto (ej: P001)
4. **horas_normales**: Horas normales trabajadas (XX.XX)
5. **horas_extras**: Horas extras trabajadas (XX.XX)
6. **tipo_turno**: DIURNO o NOCTURNO
7. **es_feriado**: SI o NO
8. **tipo_feriado**: NACIONAL, DECRETO o N/A
9. **incentivo**: Monto de incentivo calculado (XX.XX)

### Stored Procedure utilizado

**SP**: `sp_generar_reporte_nomina(fecha_inicio, fecha_fin)`

**Query ejecutado**:

```sql
SELECT
    t.fecha,
    t.empleado_id,
    p.codigo AS puesto_codigo,
    t.horas_normales,
    t.horas_extras,
    t.tipo_turno,
    CASE WHEN t.es_feriado THEN 'SI' ELSE 'NO' END AS es_feriado,
    CASE WHEN t.es_feriado THEN f.tipo ELSE 'N/A' END AS tipo_feriado,
    COALESCE(ROUND(i.valor_hora * (t.horas_normales + t.horas_extras), 2), 0) AS incentivo
FROM turnos t
INNER JOIN puestos p ON t.puesto_id = p.id
LEFT JOIN feriados f ON t.feriado_id = f.id
LEFT JOIN incentivos_puesto i ON p.id = i.puesto_id
    AND t.fecha BETWEEN i.fecha_inicio AND i.fecha_fin
WHERE t.fecha BETWEEN fecha_inicio AND fecha_fin
  AND t.procesado_nomina = FALSE
ORDER BY t.empleado_id, t.fecha;
```

**Característica clave**: Solo retorna turnos con `procesado_nomina = FALSE`

## Decisiones Técnicas Tomadas

### 1. UTF-8 con BOM
**Decisión**: Agregar BOM (`\uFEFF`) al inicio del CSV
**Razón**: Microsoft Excel requiere BOM para detectar correctamente UTF-8. Sin BOM, Excel abre el archivo con encoding incorrecto (ANSI) mostrando caracteres especiales corruptos.
**Implementación**: Agregar `\uFEFF` al inicio del string CSV en función `convertToCSV()`

### 2. Formato de decimales
**Decisión**: Usar `.toFixed(2)` para garantizar 2 decimales
**Razón**: Consistencia en el formato. Valores como `10` deben mostrarse como `10.00`, no `10`.
**Implementación**: Función auxiliar `formatearDecimal(valor)` que siempre retorna XX.XX

### 3. Valores booleanos como "SI"/"NO"
**Decisión**: Convertir booleanos a "SI"/"NO" en lugar de "true"/"false"
**Razón**: El SP ya retorna "SI"/"NO" para `es_feriado`. Mantener consistencia y claridad para usuarios hispanohablantes.
**Implementación**: El SP hace la conversión con `CASE WHEN t.es_feriado THEN 'SI' ELSE 'NO' END`

### 4. Rango máximo de 31 días
**Decisión**: Validar que el rango no exceda 31 días
**Razón**: Prevenir reportes muy grandes que puedan sobrecargar el servidor o la BD. Una quincena es 15 días, un mes es ~30 días.
**Implementación**: Validación en `generarReporteNomina()` antes de llamar al SP

### 5. Custom error para validaciones
**Decisión**: Crear `RangoFechasInvalidoError` en lugar de usar `Error` genérico
**Razón**: Permite al controller manejar específicamente errores de validación de fechas con código HTTP 400.
**Implementación**: `export class RangoFechasInvalidoError extends Error`

## Problemas Encontrados y Soluciones

### Problema 1: Formato de fecha del SP
**Problema**: MySQL retorna fechas como objetos `Date`, no como strings
**Solución**: Función `formatearFecha()` que convierte `Date` a "YYYY-MM-DD"

### Problema 2: Valores null en CSV
**Problema**: Algunos campos pueden ser null (ej: `tipo_feriado` si no es feriado)
**Solución**: Función `escaparValorCSV()` que reemplaza null por "N/A"

### Problema 3: Valores con comas
**Problema**: Si un campo contiene comas, rompe el formato CSV
**Solución**: Función `escaparValorCSV()` que envuelve valores con comas en comillas dobles y escapa comillas internas duplicándolas
