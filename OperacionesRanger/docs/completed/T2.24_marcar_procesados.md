## 1. Resumen

Se implementó el endpoint `POST /api/reportes/marcar-procesados` que permite marcar turnos como procesados después de importarlos en el sistema de nómina. Este endpoint actualiza el campo `procesado_nomina` a `TRUE` y registra el `nomina_id` asociado para todos los turnos en un rango de fechas específico, manteniendo trazabilidad y evitando duplicación de datos en futuros reportes.

### 2.1. Schema de Validación
**Archivo**: `backend/src/schemas/reporte.schema.ts`

Se agregó el schema `marcarProcesadosSchema` para validar el request body:

```typescript
export const marcarProcesadosSchema = z.object({
  body: z
    .object({
      fecha_inicio: z
        .string()
        .regex(/^\d{4}-\d{2}-\d{2}$/, 'Fecha de inicio debe estar en formato YYYY-MM-DD'),

      fecha_fin: z
        .string()
        .regex(/^\d{4}-\d{2}-\d{2}$/, 'Fecha de fin debe estar en formato YYYY-MM-DD'),

      nomina_id: z
        .number({ message: 'nomina_id es requerido y debe ser un número' })
        .int('nomina_id debe ser un número entero')
        .positive('nomina_id debe ser positivo')
    })
    .refine((data) => data.fecha_inicio <= data.fecha_fin, {
      message: 'fecha_inicio debe ser anterior o igual a fecha_fin'
    })
});
```

**Validaciones implementadas**:
- `fecha_inicio` y `fecha_fin`: formato YYYY-MM-DD (regex)
- `nomina_id`: número entero positivo
- Refinement: `fecha_inicio <= fecha_fin`

### 2.2. Service Layer
**Archivo**: `backend/src/services/reportes.service.ts`

Se agregó la función `marcarTurnosProcesados()`:

```typescript
export async function marcarTurnosProcesados(
  fecha_inicio: string,
  fecha_fin: string,
  nomina_id: number
): Promise<{
  turnos_procesados: number;
  nomina_id: number;
  fecha_inicio: string;
  fecha_fin: string;
}> {
  const pool = getTurnosPool();

  try {
    const [result] = await pool.execute<ResultSetHeader>(
      `UPDATE turnos
       SET procesado_nomina = TRUE,
           nomina_id = ?,
           updated_at = CURRENT_TIMESTAMP
       WHERE fecha BETWEEN ? AND ?
         AND procesado_nomina = FALSE`,
      [nomina_id, fecha_inicio, fecha_fin]
    );

    const turnosProcesados = result.affectedRows;

    return {
      turnos_procesados: turnosProcesados,
      nomina_id,
      fecha_inicio,
      fecha_fin,
    };
  } catch (error: any) {
    console.error('[Reportes Service] Error al marcar turnos como procesados:', error);
    throw new Error(`Error al marcar turnos como procesados: ${error.message}`);
  }
}
```

**Características**:
- Ejecuta UPDATE SQL directo con pool de conexiones
- Solo actualiza turnos NO procesados (`procesado_nomina = FALSE`)
- Retorna cantidad de turnos afectados (`affectedRows`)
- Logging de operación para trazabilidad
- Manejo de errores con mensaje descriptivo

### 2.3. Controller Layer
**Archivo**: `backend/src/controllers/reportes.controller.ts`

Se agregó el controller `marcarProcesadosController()`:

```typescript
export async function marcarProcesadosController(
  req: Request,
  res: Response
): Promise<void> {
  try {
    const { fecha_inicio, fecha_fin, nomina_id } = req.body;

    console.log(
      `[Reportes Controller] Marcando turnos como procesados: ${fecha_inicio} - ${fecha_fin}, nómina ${nomina_id}`
    );

    const result = await ReportesService.marcarTurnosProcesados(
      fecha_inicio,
      fecha_fin,
      nomina_id
    );

    console.log(
      `[Reportes Controller] ${result.turnos_procesados} turnos marcados exitosamente para nómina ${nomina_id}`
    );

    res.status(200).json(result);
  } catch (error: any) {
    console.error('[Reportes Controller] Error al marcar turnos como procesados:', error);
    res.status(500).json({
      error: 'Error interno del servidor',
      message: 'Error al marcar turnos como procesados',
    });
  }
}
```

**Características**:
- Extrae datos validados del `req.body`
- Logging de operación y resultado
- Respuesta JSON con datos del resultado
- Manejo de errores con código 500

## 3. Lógica de Negocio

### SQL Ejecutado

```sql
UPDATE turnos
SET procesado_nomina = TRUE,
    nomina_id = :nomina_id,
    updated_at = CURRENT_TIMESTAMP
WHERE fecha BETWEEN :fecha_inicio AND :fecha_fin
  AND procesado_nomina = FALSE
```

**Características clave**:
- **Inmutabilidad**: Solo actualiza turnos con `procesado_nomina = FALSE`
- **Trazabilidad**: Registra `nomina_id` para vinculación con sistema de nómina
- **Audit**: Actualiza timestamp `updated_at` automáticamente
- **Idempotencia**: Ejecutar múltiples veces con mismo `nomina_id` no causa problemas

### Flujo de Trabajo

1. **Generar Reporte**:
   ```bash
   POST /api/reportes/nomina
   Body: { fecha_inicio: "2026-01-01", fecha_fin: "2026-01-15" }
   ```
   → Descarga CSV con turnos NO procesados

2. **Importar en Sistema de Nómina**:
   - Importar CSV en sistema externo de nómina
   - Sistema genera `nomina_id` (ej: 125)

3. **Marcar Turnos como Procesados**:
   ```bash
   POST /api/reportes/marcar-procesados
   Body: { fecha_inicio: "2026-01-01", fecha_fin: "2026-01-15", nomina_id: 125 }
   ```
   → Marca turnos como procesados

4. **Futuros Reportes**:
   - Los turnos marcados NO aparecerán en futuros reportes CSV
   - El SP `sp_generar_reporte_nomina` filtra por `procesado_nomina = FALSE`
