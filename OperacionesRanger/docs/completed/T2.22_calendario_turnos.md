```typescript
// Schema para path params :año/:mes
export const calendarioParamsSchema = z.object({
  año: z
    .string()
    .regex(/^\d{4}$/, 'año debe ser un número de 4 dígitos')
    .transform((val) => parseInt(val, 10))
    .refine((val) => val >= 2000 && val <= 2100, 'año debe estar entre 2000 y 2100'),

  mes: z
    .string()
    .regex(/^\d{1,2}$/, 'mes debe ser un número de 1 o 2 dígitos')
    .transform((val) => parseInt(val, 10))
    .refine((val) => val >= 1 && val <= 12, 'mes debe estar entre 1 y 12'),
});

// Schema para query params (filtros opcionales)
export const calendarioQuerySchema = z.object({
  empleado_id: z.string().regex(/^\d+$/).transform(Number).refine(val => val > 0).optional(),
  puesto_id: z.string().regex(/^\d+$/).transform(Number).refine(val => val > 0).optional(),
  ubicacion_id: z.string().regex(/^\d+$/).transform(Number).refine(val => val > 0).optional(),
  cliente_id: z.string().regex(/^\d+$/).transform(Number).refine(val => val > 0).optional(),
});
```

**Validaciones**:
- Año: 2000-2100 (4 dígitos)
- Mes: 1-12 (1-2 dígitos)
- Filtros opcionales: números enteros positivos

### 3. Método en Service (turnos.service.ts)

**Agregado**: +140 líneas

**Método**: `getCalendarioMensual(año, mes, filtros)`

**Algoritmo implementado**:
1. Calcular rango de fechas del mes (fecha_inicio, fecha_fin)
2. Obtener todos los turnos del mes con filtros (reutiliza getTurnos())
3. Agrupar turnos por fecha en Map<string, Turno[]>
4. Query de feriados del mes (WHERE YEAR(fecha) = ? AND MONTH(fecha) = ?)
5. Generar array de días (1 al último día del mes)
6. Para cada día:
   - Obtener turnos del día (Map o array vacío)
   - Verificar si es feriado
   - Transformar turnos a TurnoCalendarioDTO
   - Agregar día a array de respuesta
7. Retornar CalendarioMensualDTO

**Optimizaciones**:
- Reutiliza getTurnos() existente (hereda todas sus optimizaciones)
- Single query para turnos del mes (pageSize=1000)
- Single query para feriados del mes
- Agrupación en memoria (eficiente con Map)
- Usa índices existentes: idx_turnos_fecha

**Manejo de fechas**:
```typescript
const fecha_inicio = `${año}-${mes.toString().padStart(2, '0')}-01`;
const ultimoDia = new Date(año, mes, 0).getDate();
const fecha_fin = `${año}-${mes.toString().padStart(2, '0')}-${ultimoDia.toString().padStart(2, '0')}`;
```

## Decisiones de Diseño

### 1. Estructura de Respuesta

**Decisión**: Incluir TODOS los días del mes, incluso sin turnos

**Razón**: Facilita el renderizado de calendarios en frontend (no tienen que generar días vacíos)

**Alternativa descartada**: Solo retornar días con turnos (requeriría lógica adicional en frontend)

---

### 2. Formato de Turnos

**Decisión**: Versión simplificada (TurnoCalendarioDTO) vs Turno completo

**Razón**: Reducir tamaño de respuesta, solo incluir datos necesarios para vista de calendario

**Datos incluidos**: empleado, puesto, ubicación, cliente (anidados), horas, tipo

**Datos excluidos**: procesado_nomina, nomina_id, observaciones, created_by, timestamps

---

### 3. Detección de Feriados

**Decisión**: Query separado a tabla feriados

**Razón**: Permite detectar feriados incluso en días sin turnos

**Implementación**: WHERE YEAR(fecha) = ? AND MONTH(fecha) = ? AND activo = 1

---

### 4. Límite de Mes

**Decisión**: Endpoint limitado a 1 mes (no permitir rangos arbitrarios)

**Razón**: Performance predecible, casos de uso claros

**Beneficio**: Máximo ~1,500 registros por request (manejable en frontend)

## Problemas Encontrados y Soluciones

### Problema 1: Conversión de Date a String

**Descripción**: MySQL retorna fechas como objetos Date, necesitan conversión a YYYY-MM-DD

**Solución**:
```typescript
const fecha = new Date(row.fecha);
const fechaStr = `${fecha.getFullYear()}-${(fecha.getMonth() + 1).toString().padStart(2, '0')}-${fecha.getDate().toString().padStart(2, '0')}`;
```

---

### Problema 2: Orden de Rutas en Router

**Descripción**: Si /calendario/:año/:mes se agrega DESPUÉS de /:id, Express interpreta "calendario" como un ID

**Solución**: Agregar ruta ANTES de /:id en turnos.routes.ts

**Documentación**: Agregada NOTA IMPORTANTE en el JSDoc de la ruta
