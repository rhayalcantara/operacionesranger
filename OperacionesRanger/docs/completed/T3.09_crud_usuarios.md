### 3. Validación de Password Fuerte

```typescript
passwordFuerteValidator() {
  return (control: AbstractControl): ValidationErrors | null => {
    const tieneMayuscula = /[A-Z]/.test(value);
    const tieneNumero = /[0-9]/.test(value);
    const tieneMinimo8 = value.length >= 8;

    return (tieneMayuscula && tieneNumero && tieneMinimo8)
      ? null
      : { passwordDebil: true };
  };
}
```

### 4. Validación de Passwords Coincidentes

```typescript
passwordsCoinciden() {
  return (formGroup: AbstractControl): ValidationErrors | null => {
    const password = formGroup.get('password')?.value;
    const confirmPassword = formGroup.get('confirm_password')?.value;

    return password === confirmPassword
      ? null
      : { passwordsNoCoinciden: true };
  };
}
```

## Decisiones Técnicas

### 1. Password en Crear vs Editar

**Decisión**: Separar formularios con/sin password.

**Razones**:
- Seguridad: No mostrar password en edición
- Claridad: Campo password solo en creación
- Backend: Endpoints separados (POST con password, PUT sin password)
- UX: Usuario sabe que para cambiar password debe usar "Reset"

### 2. Validaciones Asíncronas con Debounce

**Decisión**: AsyncValidators con debounce de 500ms.

**Razones**:
- Performance: No llamar backend en cada tecla
- UX: Esperar a que usuario termine de escribir
- Backend load: Reducir peticiones innecesarias
- RxJS best practices: debounceTime + distinctUntilChanged + switchMap

### 3. ExcludeId en Validaciones

**Decisión**: Pasar ID actual al validar unicidad en edición.

**Razones**:
- Permitir mantener mismo username/email en edición
- Backend puede excluir registro actual de la búsqueda
- Evitar falsos positivos ("Este username ya existe" cuando es el mismo)

### 4. Clipboard API vs execCommand

**Decisión**: Usar Angular CDK Clipboard.

**Razones**:
- Módulo oficial de Angular
- Abstracción sobre Clipboard API nativa
- Manejo automático de permisos
- Fallback a execCommand si no soportado

### 5. Validación de Último ADMIN

**Decisión**: Consultar contador antes de eliminar.

**Razones**:
- Prevenir eliminación del último ADMIN
- Sistema quedaría sin administradores
- Endpoint `/count/rol/ADMIN` específico
- Validación server-side adicional recomendada

## Problemas Encontrados y Soluciones

### 1. Problema: Validaciones async no se cancelaban

**Solución**: Usar `switchMap` en vez de `mergeMap`.

```typescript
switchMap(username =>
  this.usuariosService.validarUsernameUnico(username, excludeId)
)
```

`switchMap` cancela peticiones previas si hay una nueva.

### 2. Problema: Form errors no mostraban en validators custom

**Solución**: Retornar objeto con clave descriptiva.

```typescript
return { passwordDebil: true };  // NO: return false
```

Angular espera `ValidationErrors | null`, no `boolean`.

### 3. Problema: ExcludeId undefined en modo crear

**Solución**: Verificar si existe antes de usar.

```typescript
const excludeId = this.data?.usuario?.id;
// excludeId será undefined en modo crear
```

Backend debe manejar parámetro opcional.

### 4. Problema: Password mismatch no mostraba error

**Solución**: Validador a nivel FormGroup, no FormControl.

```typescript
this.usuarioForm = this.fb.group(
  { ... },
  { validators: [this.passwordsCoinciden()] } // Aquí
);
```

Validador cross-field requiere acceso a múltiples controls.
