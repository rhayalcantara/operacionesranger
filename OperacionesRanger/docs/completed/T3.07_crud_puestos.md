## Funcionalidades Implementadas

### 1. Selector Jerárquico (Cliente → Ubicación)

**Flujo**:
1. Usuario selecciona Cliente
2. Se cargan Ubicaciones de ese cliente automáticamente
3. Si cambia el cliente, se limpia la ubicación seleccionada
4. El campo ubicación está deshabilitado hasta seleccionar cliente

**Código clave**:
```typescript
setupClienteUbicacionListener(): void {
  this.puestoForm.get('cliente_id_selector')?.valueChanges
    .pipe(takeUntil(this.destroy$))
    .subscribe((clienteId) => {
      this.puestoForm.patchValue({ ubicacion_id: null });
      this.ubicacionesDisponibles = [];

      if (clienteId) {
        this.cargarUbicacionesPorCliente(clienteId);
      }
    });
}
```

### 2. Filtros Jerárquicos en Lista

**Filtros disponibles**:
- **Cliente**: Mat-select con clientes activos
- **Ubicación**: Mat-select filtrado por cliente (se actualiza dinámicamente)
- **Búsqueda**: Input con debounce 500ms (busca en código y nombre)

**Comportamiento**:
- Al cambiar cliente → se cargan ubicaciones de ese cliente → se filtra la tabla
- Al cambiar ubicación → se filtra la tabla
- Todos los filtros resetean la paginación a página 1

### 3. Validaciones

**Validaciones síncronas**:
- `codigo`: requerido
- `nombre`: requerido, minLength 3, maxLength 100
- `descripcion`: maxLength 500
- `horario_esperado`: pattern `/^\d{2}:\d{2}-\d{2}:\d{2}$/` + lógica (hora_fin > hora_inicio)
- `cliente_id_selector`: requerido (solo para UI)
- `ubicacion_id`: requerido

**Validación asíncrona**:
- `codigo`: Verifica unicidad dentro de la ubicación
- Endpoint: `GET /api/puestos/validar-codigo?ubicacion_id=1&codigo=P001&excludeId=123`
- Debounce 500ms para evitar llamadas excesivas
- Muestra spinner inline durante validación

**Validador de horario**:
```typescript
horarioValidator(): (control: AbstractControl) => ValidationErrors | null {
  return (control: AbstractControl): ValidationErrors | null => {
    if (!control.value) return null;

    const pattern = /^\d{2}:\d{2}-\d{2}:\d{2}$/;
    if (!pattern.test(control.value)) {
      return { formatoInvalido: true };
    }

    const [inicio, fin] = control.value.split('-');
    if (inicio >= fin) {
      return { horarioInvalido: true };
    }

    return null;
  };
}
```

## Notas Técnicas

### 1. Manejo de Memoria

Se implementó el patrón `takeUntil(destroy$)` en todas las suscripciones para evitar memory leaks:

```typescript
private destroy$ = new Subject<void>();

ngOnInit(): void {
  this.searchControl.valueChanges
    .pipe(takeUntil(this.destroy$))
    .subscribe(...);
}

ngOnDestroy(): void {
  this.destroy$.next();
  this.destroy$.complete();
}
```

### 2. Async Validator Optimizado

El async validator usa `debounceTime` y `switchMap` para:
- Evitar validaciones mientras el usuario escribe
- Cancelar requests anteriores si hay uno nuevo
- Solo validar cuando hay ubicación seleccionada

### 3. Selector Jerárquico

El campo `cliente_id_selector` es **solo para la UI**. No se envía al backend:

```typescript
onSubmit(): void {
  const { cliente_id_selector, ...puestoData } = this.puestoForm.value;
  // Solo se envía puestoData (sin cliente_id_selector)
}
```

### 4. Re-validación Inteligente

Al cambiar cliente o ubicación, se re-valida el código automáticamente:

```typescript
this.puestoForm.get('ubicacion_id')?.valueChanges
  .pipe(takeUntil(this.destroy$))
  .subscribe(() => {
    this.puestoForm.get('codigo')?.updateValueAndValidity();
  });
```
