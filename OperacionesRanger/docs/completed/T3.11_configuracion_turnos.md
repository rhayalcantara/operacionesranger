## Descripción

Implementación del componente de configuración de horarios de turnos (DIURNO y NOCTURNO). A diferencia de otros CRUDs, este componente es de tipo UPDATE-ONLY, ya que solo existen dos registros fijos en la base de datos que deben ser editados.

## Características Especiales

### 1. UPDATE-ONLY Component

A diferencia de otros CRUDs del sistema, este componente NO permite:
- ❌ Crear nuevos registros (CREATE)
- ❌ Eliminar registros (DELETE)

Solo permite:
- ✅ Leer configuraciones existentes (READ)
- ✅ Actualizar configuraciones existentes (UPDATE)

**Razón**: Solo existen 2 registros fijos en la base de datos (DIURNO y NOCTURNO) que deben ser editados, no creados ni eliminados.

### 2. Validación de Horarios Contiguos

Los horarios de los turnos deben ser **contiguos** (sin espacios ni solapamientos):

```
DIURNO:   06:00 ───────────────> 18:00
                                  ↓
NOCTURNO:                     18:00 ───────────────> 06:00 (siguiente día)
                                                      ↓
DIURNO:                                           06:00 ───────────>
```

**Validaciones Implementadas**:
- `hora_fin_diurno === hora_inicio_nocturno`
- `hora_fin_nocturno === hora_inicio_diurno`

### 3. Actualización Simultánea

Ambas configuraciones se actualizan **simultáneamente** usando RxJS `forkJoin`:

```typescript
forkJoin({
  diurno: this.configuracionService.update(idDiurno, dataDiurno),
  nocturno: this.configuracionService.update(idNocturno, dataNocturno)
}).subscribe({
  next: (results) => {
    // Ambas actualizaciones exitosas
  }
});
```

**Ventaja**: Si una falla, ambas fallan (atomicidad).

### 4. Control de Acceso por Rol

**Solo ADMIN puede editar**:
```typescript
ngOnInit(): void {
  this.loadConfiguraciones();

  if (!this.isAdmin()) {
    this.diurnoForm.disable(); // Deshabilitar formularios
    this.nocturnoForm.disable();
  }
}
```

**Usuarios no-ADMIN**:
- Pueden **ver** las configuraciones (read-only)
- No pueden **editar** (formularios deshabilitados)
- No ven botones de acción

### 5. Conversión de Formatos de Hora

**Backend**: `"HH:mm:ss"` (06:00:00)
**Frontend**: `"HH:mm"` (06:00)

**Conversiones Automáticas**:
```typescript
// Backend → Frontend
formatTimeForForm('06:00:00') → '06:00'

// Frontend → Backend
formatTimeForBackend('06:00') → '06:00:00'
```

### 6. Resumen Visual de Horarios

Cada tarjeta muestra un resumen visual del rango horario seleccionado:

```html

  <mat-icon>schedule</mat-icon>
  <span class="time-range">06:00 - 18:00</span>
</div>
```

Con gradiente y borde de color según el tipo de turno.

## Validaciones del Frontend

### 1. Validaciones de Formulario

**Hora de Inicio / Fin**:
- ✅ Required
- ✅ Pattern: `/^\d{2}:\d{2}$/` (formato HH:mm)

**Descripción**:
- ✅ Opcional
- ✅ Sin límite de caracteres

**Activo**:
- ✅ Boolean (checkbox)

### 2. Validaciones de Negocio

**Horarios Contiguos**:
```typescript
validateNoOverlap(
  diurnoInicio: '06:00',
  diurnoFin: '18:00',
  nocturnoInicio: '18:00',
  nocturnoFin: '06:00'
)
```

**Casos de Error**:
- ❌ `diurnoInicio >= diurnoFin`
  - Mensaje: "Turno DIURNO: La hora de inicio debe ser menor a la hora de fin"
- ❌ `diFin !== noInicio`
  - Mensaje: "El turno DIURNO debe terminar exactamente cuando comienza el turno NOCTURNO"
- ❌ `noFin !== diInicio`
  - Mensaje: "El turno NOCTURNO debe terminar exactamente cuando comienza el turno DIURNO"

### 3. Validaciones de Permisos

**Control de Acceso**:
```typescript
if (!this.isAdmin()) {
  this.diurnoForm.disable();
  this.nocturnoForm.disable();
}
```

## Notas Técnicas

### 1. Uso de forkJoin

Se usa `forkJoin` de RxJS para actualizar ambas configuraciones en paralelo:

**Ventajas**:
- Espera a que ambas peticiones terminen
- Si una falla, ambas fallan (atomicidad)
- Más rápido que secuencial

**Alternativa Descartada**: Actualizar secuencialmente con `switchMap`

### 2. Input Type="time"

Se usa el input nativo del navegador `type="time"`:

**Ventajas**:
- Interfaz consistente con el sistema operativo
- Validación nativa de formato
- Accesibilidad mejorada

**Limitaciones**:
- Estilo limitado en algunos navegadores
- Formato 12h/24h depende del sistema operativo

### 3. Standalone Components

El componente usa `standalone: true`:

**Ventajas**:
- No necesita módulo contenedor
- Importa solo lo que usa
- Lazy loading más eficiente

### 4. RoleGuard en Ruta

La protección se hace en dos niveles:
1. **Ruta**: `roleGuard` con `data: { roles: ['ADMIN'] }`
2. **Componente**: `isAdmin()` deshabilita formularios

**Razón**: Defensa en profundidad (defense in depth).
