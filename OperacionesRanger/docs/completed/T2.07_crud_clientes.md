### [✓] 3. Crear servicio clientes.service.ts (60 min)

**Archivo**: `backend/src/services/clientes.service.ts`

**Funciones implementadas**:

1. **getClientes(page, pageSize, search)**: Listar con paginación
   - Búsqueda por nombre, código, RNC (LIKE %search%)
   - Paginación con LIMIT/OFFSET
   - Retorna: `{ data, total, page, pageSize, totalPages }`

2. **getClienteById(id)**: Obtener por ID
   - JOIN con ubicaciones para count
   - Retorna: Cliente + ubicaciones_count

3. **createCliente(data)**: Crear nuevo cliente
   - Valida código único
   - Valida RNC único (si provisto)
   - Normaliza RNC antes de INSERT
   - Retorna: Cliente creado con ID

4. **updateCliente(id, data)**: Actualizar cliente
   - Valida que cliente existe
   - Valida código único (si cambia)
   - Valida RNC único (si cambia)
   - UPDATE dinámico (solo campos provistos)
   - Retorna: Cliente actualizado

5. **deleteCliente(id)**: Soft delete
   - Valida que cliente existe
   - Valida que NO tenga ubicaciones activas
   - UPDATE activo = FALSE
   - Error 409 si tiene ubicaciones activas

**Funciones auxiliares**:
- `codigoExists()`: Verifica código duplicado
- `rncExists()`: Verifica RNC duplicado
- `countUbicacionesActivas()`: Count de ubicaciones del cliente

## Decisiones Técnicas Tomadas

### 1. Normalización de RNC

**Decisión**: Normalizar RNC eliminando guiones y espacios antes de INSERT/UPDATE

**Justificación**:
- Facilita validación de duplicados
- Formato consistente en BD
- Se puede formatear en frontend para visualización

**Implementación**: Función `normalizeRNC()` en cliente.model.ts

---

### 2. Soft Delete con validación de FK

**Decisión**: No permitir soft delete si cliente tiene ubicaciones activas

**Justificación**:
- Mantener integridad referencial
- Evitar datos huérfanos
- Forzar cleanup de ubicaciones antes de eliminar cliente

**Implementación**: Query COUNT en clientes.service.deleteCliente()

---

### 3. Búsqueda Flexible

**Decisión**: Buscar en 3 campos: nombre, código, RNC con OR

**Justificación**:
- UX mejorada (usuario no necesita especificar campo)
- Búsqueda más intuitiva
- Performance aceptable con índices en BD

**Implementación**: WHERE clause con múltiples LIKE en clientes.service.getClientes()

---

### 4. Paginación Server-Side

**Decisión**: Implementar paginación en backend con LIMIT/OFFSET

**Justificación**:
- Performance con tablas grandes
- Reducir payload de red
- Estándar en APIs REST

**Implementación**: Query con LIMIT/OFFSET, COUNT separado para total
