**Descripción**: El turno NOCTURNO (18:00-06:00) cruza medianoche, lo cual complica la validación.

**Solución**: Implementar lógica especial en el modelo:

- Validación de complementariedad usando comparación directa de strings TIME
- No intentar convertir a rangos absolutos, solo verificar que un turno termine donde empieza el otro

**Tiempo invertido**: 15 minutos

## Decisiones Técnicas Tomadas

### Decisión 1: No permitir CREATE ni DELETE
**Razón**: Las 2 configuraciones (DIURNO y NOCTURNO) son esenciales para el sistema y no deben crearse ni eliminarse. Solo se actualizan.

**Implementación**:
- No se crearon controladores para POST y DELETE
- Se agregaron handlers que retornan 405 Method Not Allowed con mensaje explicativo
- Los tests verifican que estos métodos están bloqueados

### Decisión 2: Validación de horarios complementarios
**Razón**: Los horarios DIURNO y NOCTURNO deben cubrir exactamente 24 horas sin solapamiento.

**Implementación**:
- Validación en servicio: `validateHorariosConOtroTurno()`
- Verifica que DIURNO.hora_fin === NOCTURNO.hora_inicio
- Verifica que NOCTURNO.hora_fin === DIURNO.hora_inicio
- Si no se cumple, lanza error descriptivo

### Decisión 3: Aceptar formato HH:MM y HH:MM:SS
**Razón**: Mejor UX - permitir que el usuario ingrese horarios con o sin segundos.

**Implementación**:
- Regex en schema Zod acepta ambos formatos
- Función `normalizeTime()` agrega `:00` si solo es HH:MM
- MySQL almacena siempre como HH:MM:SS

### Decisión 4: Solo ADMIN puede actualizar
**Razón**: Cambiar los horarios de turnos afecta la clasificación de todos los turnos registrados, es una operación crítica.

**Implementación**:
- Middleware `requireRole(UserRole.ADMIN)` en ruta PUT
- SUPERVISOR puede consultar pero no modificar
- Tests verifican que SUPERVISOR recibe 403 Forbidden

## Notas Adicionales

### Integración con sp_determinar_tipo_turno

Los horarios configurados en esta tabla son usados por el stored procedure `sp_determinar_tipo_turno` para clasificar automáticamente cada turno registrado como DIURNO o NOCTURNO.

**Flujo**:
1. Usuario registra turno con hora de entrada (ej: 08:00)
2. SP ejecuta: `SELECT hora_inicio, hora_fin FROM configuracion_turnos WHERE tipo_turno = 'DIURNO'`
3. SP compara: `IF hora_entrada >= hora_inicio_diurno AND hora_entrada < hora_fin_diurno THEN 'DIURNO' ELSE 'NOCTURNO'`

**Advertencia**: Cambiar los horarios afecta la clasificación de TODOS los turnos futuros. Los turnos ya registrados NO se reclasifican automáticamente.
