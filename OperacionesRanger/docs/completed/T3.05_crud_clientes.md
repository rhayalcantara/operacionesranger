### Async Validator

El validador de RUC único implementa:
- Debounce de 500ms para evitar requests excesivos
- DistinctUntilChanged para optimizar
- Exclusión del ID actual en modo edición
- Manejo de errores con fallback a null

```typescript
rucUnicoValidator(): AsyncValidatorFn {
  return (control: AbstractControl): Observable<ValidationErrors | null> => {
    if (!control.value) return of(null);

    const excludeId = this.data?.cliente?.id;
    return of(control.value).pipe(
      debounceTime(500),
      distinctUntilChanged(),
      switchMap(ruc =>
        this.clientesService.validarRucUnico(ruc, excludeId).pipe(
          map(esUnico => esUnico ? null : { rucDuplicado: true }),
          catchError(() => of(null))
        )
      ),
      first()
    );
  };
}
```

## Problemas Encontrados y Soluciones

### 1. Error de compilación en módulo puestos

**Problema**: Durante la primera compilación, apareció un error de TypeScript en `puestos.component.ts` indicando que no podía resolver `./puesto-form/puesto-form.component`.

**Causa**: Caché del compilador Angular desactualizado (directorio `.angular`).

**Solución**: Limpiar el caché con `rm -rf .angular` y recompilar. El error se resolvió automáticamente.

### 2. Imports faltantes en ClientesComponent

**Problema**: Template HTML usaba `<mat-card>` pero no estaba importado en el componente.

**Causa**: Olvido de agregar `MatCardModule` al array de imports.

**Solución**: Agregado `MatCardModule` a los imports del componente standalone.

### 3. Budget warnings

**Problema**: Warnings de presupuesto excedido en bundle inicial y algunos estilos.

**Causa**: Angular Material es pesado, especialmente cuando se importan muchos módulos.

**Solución**: ⚠️ No crítico. Se aceptan los warnings. Para producción se puede:
- Implementar lazy loading más agresivo
- Usar standalone components más granulares
- Considerar custom theme de Material más liviano
