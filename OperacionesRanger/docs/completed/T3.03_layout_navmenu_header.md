### Mock de AuthService

Dado que T3.02 está ejecutándose en paralelo, se creó un mock temporal de AuthService en ambos componentes (NavMenuComponent y HeaderComponent):

```typescript
interface MockAuthService {
  getCurrentUser(): { id: number; username: string; rol: string; nombre_completo: string } | null;
  hasRole(...roles: string[]): boolean;
  logout(): void; // Solo en HeaderComponent
}

private mockAuthService: MockAuthService = {
  getCurrentUser: () => ({
    id: 1,
    username: 'admin',
    rol: 'ADMIN',
    nombre_completo: 'Administrador del Sistema'
  }),
  hasRole: (...roles: string[]) => {
    const user = this.mockAuthService.getCurrentUser();
    return user ? roles.includes(user.rol) : false;
  }
};
```

### Breakpoints Responsivos

Se utilizó `BreakpointObserver` de Angular CDK Layout:

- **isHandset$**: Detecta handset (mobile + tablet)
- **isMobile$**: Detecta mobile (<768px)
- **isTablet$**: Detecta tablet (768-1024px)
- **isDesktop$**: Detecta desktop (>1024px)

Estos observables controlan:
- Modo del sidenav: `[mode]="(isMobile$ | async) ? 'over' : 'side'"`
- Apertura inicial: `[opened]="(isDesktop$ | async) ? true : false"`
- Visibilidad del toggle button
- Ancho del sidebar (CSS media queries)

## Decisiones Técnicas Tomadas

### 1. Mock de AuthService
**Decisión**: Crear mock temporal en lugar de esperar a T3.02
**Justificación**: Permite desarrollo independiente y testing temprano. El mock será reemplazado fácilmente por inyección de dependencia real.

### 2. Uso de BreakpointObserver
**Decisión**: Usar observables para responsive en lugar de solo CSS media queries
**Justificación**: Mayor control sobre la lógica de presentación desde TypeScript, permite cambiar comportamiento dinámicamente.

### 3. Estructura de menuItems como array
**Decisión**: Definir menuItems como array de objetos con interface MenuItem
**Justificación**: Facilita mantenimiento, permite agregar/modificar items fácilmente, estructura clara y tipada.

### 4. Submenu expandible con estado local
**Decisión**: Controlar expansión de submenus con propiedad `expanded` en cada item
**Justificación**: Simple y eficiente, no requiere servicio externo, estado localizado en el componente.

### 5. Badges de rol con colores
**Decisión**: Asignar colores específicos por rol (Admin=rojo, Supervisor=naranja, Consulta=verde)
**Justificación**: Identificación visual rápida del rol del usuario, consistente con sistemas similares.

### 6. Logo con icono Material `security`
**Decisión**: Usar icono `security` en lugar de logo personalizado
**Justificación**: Apropiado para sistema de seguridad/guardianes, no requiere assets adicionales, escalable.
