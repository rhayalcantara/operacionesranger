## Decisiones Técnicas Tomadas

1. **Uso de Stored Procedure para verificación de feriados**
   - **Decisión**: Llamar a `sp_verificar_feriado` en endpoint GET /verificar/:fecha
   - **Justificación**: El SP ya existe en la BD y contiene la lógica de verificación. Reutilizar en vez de duplicar lógica.
   - **Implementación**: Usar `CALL sp_verificar_feriado(?, @var1, @var2, @var3)` seguido de `SELECT @var1, @var2, @var3` para obtener OUT parameters.

2. **Hard delete en vez de soft delete**
   - **Decisión**: DELETE permanente sin campo `activo`
   - **Justificación**: Los feriados son datos maestros que no necesitan trazabilidad histórica. Si se eliminan es porque fueron ingresados por error.

3. **Validación de duplicados a nivel de BD**
   - **Decisión**: Confiar en constraint `uk_fecha` de MySQL
   - **Justificación**: La BD garantiza unicidad. El servicio captura error `ER_DUP_ENTRY` y retorna 409 Conflict.

4. **Paginación server-side obligatoria**
   - **Decisión**: Siempre paginar, incluso si no se especifica page/pageSize
   - **Justificación**: Los feriados crecen año a año. Evitar cargar 100+ registros de una vez.

5. **Permisos estrictos para CUD**
   - **Decisión**: Solo ADMIN puede crear, actualizar y eliminar feriados
   - **Justificación**: Los feriados afectan cálculos de nómina. Deben ser gestionados solo por administradores del sistema.

6. **Corrección de errores de otros subagentes**
   - **Decisión**: Corregir errores de TypeScript que bloqueaban compilación
   - **Justificación**: Los errores impedían ejecutar tests de feriados. Se aplicaron correcciones mínimas sin alterar lógica.

## Integración con Stored Procedure

El endpoint `/api/feriados/verificar/:fecha` utiliza el stored procedure `sp_verificar_feriado`:

```sql
CALL sp_verificar_feriado(
    IN p_fecha DATE,
    OUT p_es_feriado BOOLEAN,
    OUT p_feriado_id INT,
    OUT p_tipo_feriado VARCHAR(20)
)
```

**Implementación en Node.js**:
```typescript
await pool.query('CALL sp_verificar_feriado(?, @es_feriado, @feriado_id, @tipo_feriado)', [fecha]);

const [resultRows] = await pool.query<RowDataPacket[]>(
  'SELECT @es_feriado as es_feriado, @feriado_id as feriado_id, @tipo_feriado as tipo_feriado'
);
```

El SP retorna OUT parameters que se consultan en una segunda query.
