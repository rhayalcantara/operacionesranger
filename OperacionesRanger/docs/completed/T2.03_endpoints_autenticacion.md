## Subtareas Completadas

### 1. ✅ Crear servicio de autenticación (auth.service.ts)

**Archivo**: `backend/src/services/auth.service.ts`

**Funciones implementadas**:

#### `login(username, password, ip?, userAgent?): Promise<LoginResponseDTO>`
- Busca usuario por username en `sys_usuarios`
- Valida que usuario exista, esté activo, y no esté bloqueado temporalmente
- Compara password con bcrypt usando `password.service.verifyPassword()`
- Si password es incorrecta:
  - Incrementa `intentos_fallidos`
  - Bloquea usuario por 15 minutos tras 5 intentos fallidos
  - Registra auditoría `LOGIN_FAILED`
- Si password es correcta:
  - Resetea `intentos_fallidos` a 0
  - Actualiza `ultimo_login`
  - Genera access token (30 minutos) y refresh token (7 días)
  - Hashea refresh token (SHA-256) y almacena en `sys_refresh_tokens`
  - Registra auditoría `LOGIN_SUCCESS`
  - Retorna `{ accessToken, refreshToken, user }` sin `password_hash`

#### `refreshAccessToken(refreshToken): Promise<{ accessToken }>`
- Verifica firma y expiración del refresh token (JWT)
- Hashea token y busca en `sys_refresh_tokens`
- Valida que no esté revocado y no esté expirado en BD
- Obtiene usuario asociado y valida que esté activo
- Genera nuevo access token
- Registra auditoría `TOKEN_REFRESH`

#### `logout(refreshToken, userId): Promise<void>`
- Hashea refresh token (SHA-256)
- Busca token en `sys_refresh_tokens`
- Marca como revocado con `fecha_revocacion = NOW()`
- Registra auditoría `LOGOUT`

#### `changePassword(userId, currentPassword, newPassword): Promise<void>`
- Busca usuario por ID
- Verifica password actual con bcrypt
- Hashea nueva password con bcrypt
- Actualiza `password_hash` en BD
- Registra auditoría `PASSWORD_CHANGE`

#### `createAuditLog(auditData): Promise<void>`
- Helper interno para registrar eventos en `sys_auditoria_auth`
- Convierte `detalles` a JSON string si es objeto
- Registra: `id_usuario`, `username`, `evento`, `ip_address`, `user_agent`, `detalles`

**Resultado**: Servicio completo con manejo de transacciones, validaciones de negocio, y auditoría robusta.

### 2. ✅ Crear controlador de autenticación (auth.controller.ts)

**Archivo**: `backend/src/controllers/auth.controller.ts`

**Controllers implementados**:

#### `loginController(req, res, next)`
- Valida body con `loginSchema` (Zod)
- Extrae IP (`req.ip` o `X-Forwarded-For`) y User-Agent
- Llama a `auth.service.login()`
- Respuestas:
  - 200 OK: `{ accessToken, refreshToken, user }`
  - 401 Unauthorized: Credenciales inválidas o usuario inactivo
  - 403 Forbidden: Usuario bloqueado temporalmente

#### `refreshTokenController(req, res, next)`
- Valida body con `refreshTokenSchema`
- Llama a `auth.service.refreshAccessToken()`
- Respuestas:
  - 200 OK: `{ accessToken }`
  - 401 Unauthorized: Token inválido/expirado/revocado

#### `logoutController(req: AuthenticatedRequest, res, next)`
- **Requiere**: `authMiddleware` que agregue `req.user` (de T2.04)
- Valida body con `logoutSchema`
- Extrae `userId` de `req.user.sub`
- Llama a `auth.service.logout()`
- Respuestas:
  - 200 OK: `{ message: "Logout exitoso" }`
  - 401 Unauthorized: No autenticado (si middleware no disponible)

#### `changePasswordController(req: AuthenticatedRequest, res, next)`
- **Requiere**: `authMiddleware` (de T2.04)
- Valida body con `changePasswordSchema`
- Extrae `userId` de `req.user.sub`
- Llama a `auth.service.changePassword()`
- Respuestas:
  - 200 OK: `{ message: "Contraseña actualizada exitosamente" }`
  - 401 Unauthorized: Password actual incorrecta o no autenticado
  - 400 Bad Request: Validación fallida (password débil)

**Funciones de utilidad**:
- `getClientIp(req)`: Extrae IP del cliente (prioriza `X-Forwarded-For`)
- `getUserAgent(req)`: Extrae User-Agent del request

**Resultado**: 4 controllers funcionando con validación, extracción de datos contextuales, y manejo de errores.

## Decisiones Técnicas Tomadas

### 1. Hashing de refresh tokens con SHA-256
**Decisión**: Almacenar refresh tokens hasheados en BD (SHA-256), no en texto plano.

**Justificación**:
- Seguridad: Si BD es comprometida, tokens no son directamente utilizables
- Performance: SHA-256 es más rápido que bcrypt para este caso de uso
- Cumple con ADR-002

**Implementación**:
```typescript
const tokenHash = crypto.createHash('sha256').update(refreshToken).digest('hex');
```

---

### 2. Bloqueo automático por intentos fallidos
**Decisión**: Bloquear usuario por 15 minutos tras 5 intentos fallidos.

**Justificación**:
- Prevención de ataques de fuerza bruta
- Configurable en `LOGIN_SECURITY.MAX_LOGIN_ATTEMPTS` y `LOCKOUT_DURATION_MINUTES`
- Cumple con mejores prácticas de seguridad

**Implementación**:
- Incremento de `intentos_fallidos` en cada login fallido
- Campo `bloqueado_hasta` con timestamp futuro
- Validación de `isUserLocked(usuario)` antes de verificar password

---

### 3. Extracción de IP con prioridad de X-Forwarded-For
**Decisión**: Priorizar header `X-Forwarded-For` sobre `req.ip` para obtener IP del cliente.

**Justificación**:
- Compatibilidad con proxies reversos (nginx, load balancers)
- Obtiene IP real del cliente en lugar de IP del proxy
- Necesario para auditoría precisa

**Implementación**:
```typescript
function getClientIp(req: Request): string | undefined {
  const forwardedFor = req.headers['x-forwarded-for'];
  if (forwardedFor) {
    return Array.isArray(forwardedFor) ? forwardedFor[0] : forwardedFor.split(',')[0].trim();
  }
  return req.ip;
}
```

---

### 4. No revelar si usuario existe o no
**Decisión**: Usar mensaje genérico "Usuario o contraseña incorrectos" tanto para usuario inexistente como password incorrecta.

**Justificación**:
- Seguridad: Prevenir enumeración de usuarios válidos
- Cumple con OWASP Authentication Cheat Sheet
- Mejora privacidad

---

### 5. Auditoría incluso en errores
**Decisión**: Registrar auditoría tanto para login exitoso como fallido.

**Justificación**:
- Trazabilidad completa de intentos de acceso
- Detección de ataques de fuerza bruta
- Cumplimiento de requisitos de auditoría de ADR-002

---

### 6. Coordinación con T2.04 (Middleware de autenticación)

**Justificación**:
- T2.04 se ejecuta EN PARALELO, no está disponible aún
- Los controllers validan si `req.user` existe, retornan 401 si no
- Los tests detectan automáticamente si middleware está disponible
- Fácil integración cuando T2.04 complete (solo descomentar middleware)
