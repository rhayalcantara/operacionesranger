## Problemas Encontrados y Soluciones

### Problema 1: Componentes de layout no eran standalone

**Error**:
```
NG8001: 'mat-icon' is not a known element
NG8002: Can't bind to 'routerLink' since it isn't a known property
```

**Causa**: LayoutComponent, HeaderComponent, y NavMenuComponent fueron creados como componentes tradicionales (con NgModule), pero no había módulo que los declarara.

**Solución**: Convertir todos los componentes de layout a **standalone components** con imports explícitos de Material y Router.

---

### Problema 2: Error de inicialización en LayoutComponent

**Error**:
```
TS2729: Property 'breakpointObserver' is used before its initialization.
```

**Causa**: Los observables (`isHandset$`, `isMobile$`, etc.) se inicializaban como propiedades de clase antes de que el constructor corriera, pero referenciaban `this.breakpointObserver` que no existía aún.

**Solución**: Usar Angular `inject()` function en lugar de inyección en constructor:

```typescript
// ANTES
constructor(private breakpointObserver: BreakpointObserver) {}
isHandset$ = this.breakpointObserver.observe(...);  // ❌ Error

// DESPUÉS
private breakpointObserver = inject(BreakpointObserver);
isHandset$ = this.breakpointObserver.observe(...);  // ✅ OK
```

---

### Problema 3: Tipo incorrecto en hasRole()

**Error**:
```
TS2345: Argument of type 'string[]' is not assignable to parameter of type 'UserRole'.
```

**Causa**: El método `AuthService.hasRole()` usa rest parameter (`...roles: UserRole[]`), no acepta un array directamente.

**Solución**: Usar spread operator:

```typescript
// ANTES
this.authService.hasRole(item.roles);  // ❌ Error

// DESPUÉS
this.authService.hasRole(...item.roles as any);  // ✅ OK
```

---

### Problema 4: Módulos referenciados en rutas no existían

**Error**:
```
TS2307: Cannot find module './modules/clientes/clientes.component'
Could not resolve "./modules/clientes/clientes.component"
```

**Causa**: Las rutas referenciaban componentes que aún no habían sido creados.

**Solución**: Crear componentes stub simples para cada módulo (ver sección 7).

---

### Problema 5: MatDividerModule faltante en HeaderComponent

**Error**:
```
NG8001: 'mat-divider' is not a known element
```

**Solución**: Agregar `MatDividerModule` a los imports de HeaderComponent.

## Flujo de Autenticación Implementado

### 1. Login

```
Usuario → LoginComponent
   ↓
AuthService.login(username, password)
   ↓
Backend /api/auth/login
   ↓
JWT Token guardado en localStorage
   ↓
Router.navigate(['/dashboard'])
```

### 2. Acceso a Ruta Protegida

```
Usuario navega a /dashboard
   ↓
authGuard.canActivate()
   ↓
¿Token válido?
   ├─ Sí → Permite acceso
   └─ No → Redirige a /login
```

### 3. Acceso a Ruta con Rol

```
Usuario navega a /usuarios
   ↓
authGuard.canActivate() ✅
   ↓
roleGuard.canActivate()
   ↓
¿Rol ADMIN?
   ├─ Sí → Permite acceso
   └─ No → Redirige a /unauthorized
```

### 4. Logout

```
Usuario → HeaderComponent → onLogout()
   ↓
AuthService.logout()
   ↓
Backend /api/auth/logout (invalidar refresh token)
   ↓
localStorage.removeItem('jwt_token')
   ↓
Router.navigate(['/login'])
```

## Lecciones Aprendidas

### 1. Importancia de la Exploración Inicial

El hallazgo de que el proyecto **ya existía** ahorró ~1.5 horas de trabajo. Explorar antes de planear es crítico.

### 2. Standalone Components como Estándar

Angular 21 favorece standalone components. Convertir componentes tradicionales a standalone evita problemas de módulos y simplifica la arquitectura.

### 3. Uso de `inject()` vs Constructor Injection

En standalone components, `inject()` es más flexible y evita problemas de orden de inicialización.

### 4. Stub Components para Desarrollo Paralelo

Crear stubs permite que las rutas compilen mientras otros desarrolladores trabajan en los módulos completos.

### 5. Lazy Loading Agresivo

Lazy loading de todos los módulos reduce el bundle inicial y mejora performance.
