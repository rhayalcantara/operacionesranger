## Arquitectura Implementada

### Flujo de Middleware en Requests

```
Cliente HTTP
    ↓
[1] CORS + JSON Parser
    ↓
[2] authMiddleware (JWT validation)
    ↓
[3] roleMiddleware (Authorization)
    ↓
[4] paginationMiddleware (solo GET list) - Agrega req.pagination
    ↓
[5] validateParams / validateBody / validateQuery - Agrega req.validatedData
    ↓
[6] Controller (Business Logic)
    ↓
[7] Response
    ↓
[8] errorHandlerMiddleware (si hay error)
```

#### Respuesta Exitosa con Paginación

## Características Implementadas

### 1. Validation Middleware

**Archivo**: `src/middlewares/validation.middleware.ts`

**Características**:
- Validación automática con Zod schemas
- Funciones especializadas: `validateBody`, `validateQuery`, `validateParams`
- Formateo consistente de errores
- Datos validados en `req.validatedData`
- Respuesta 400 automática si falla

**Uso**:
```typescript
import { validateBody, validateParams } from '../middlewares/validation.middleware';
import { createClienteSchema, clienteIdParamSchema } from '../schemas/cliente.schema';

router.post(
  '/',
  authMiddleware,
  requireRole('ADMIN', 'SUPERVISOR'),
  validateBody(createClienteSchema),
  createCliente
);

router.put(
  '/:id',
  authMiddleware,
  requireRole('ADMIN', 'SUPERVISOR'),
  validateParams(clienteIdParamSchema),
  validateBody(updateClienteSchema),
  updateCliente
);
```

### 2. Pagination Middleware

**Archivo**: `src/middlewares/pagination.middleware.ts`

**Características**:
- Parsea `page` y `pageSize` de query params
- Valores por defecto: page=1, pageSize=10
- Límite máximo: pageSize=100
- Calcula offset automáticamente: `(page - 1) * pageSize`
- Agrega a `req.pagination` los valores validados

**Configuración**:
```typescript
export const PAGINATION_CONFIG = {
  DEFAULT_PAGE: 1,
  DEFAULT_PAGE_SIZE: 10,
  MIN_PAGE_SIZE: 1,
  MAX_PAGE_SIZE: 100
} as const;
```

**Uso**:
```typescript
import { paginationMiddleware } from '../middlewares/pagination.middleware';

router.get(
  '/',
  authMiddleware,
  requireRole('ADMIN', 'SUPERVISOR', 'CONSULTA'),
  paginationMiddleware,
  getClientes
);

// En controller:
export async function getClientes(req: Request, res: Response) {
  const { page, pageSize, offset } = req.pagination!;
  // ... usar en query SQL
}
```

### 3. Error Handler Middleware

**Archivo**: `src/middlewares/error-handler.middleware.ts`

**Características**:
- Captura todos los errores no manejados
- Detecta tipo de error automáticamente:
  - ZodError → 400 Bad Request
  - Custom Errors (con statusCode) → Usa statusCode
  - MySQL Errors → Mapea a códigos HTTP apropiados
  - Errores genéricos → 500 Internal Server Error
- Logging con contexto completo
- Stack traces solo en development

**Mapeo de Errores MySQL**:
```typescript
ER_DUP_ENTRY → 409 Conflict
ER_NO_REFERENCED_ROW → 404 Not Found
ER_ROW_IS_REFERENCED → 409 Conflict
ER_BAD_NULL_ERROR → 400 Bad Request
ER_DATA_TOO_LONG → 400 Bad Request
ECONNREFUSED → 503 Service Unavailable
```

**Registro en Server**:
```typescript
// IMPORTANTE: Debe ser el ÚLTIMO middleware
app.use(errorHandlerMiddleware);
```

## Ejemplos de Uso

### Ejemplo 1: Crear Cliente con Validación

**Request**:
```http
POST /api/clientes
Authorization: Bearer <token>
Content-Type: application/json

{
  "codigo": "CLI001",
  "nombre": "Banco Popular",
  "rnc": "101-50047-5",
  "telefono": "809-544-5000"
}
```

**Flujo**:
1. `authMiddleware` → Valida JWT
2. `roleMiddleware` → Verifica rol (ADMIN o SUPERVISOR)
3. `validateBody(createClienteSchema)` → Valida datos con Zod
4. Controller → Crea cliente en BD
5. Response 201 Created

**Si validación falla**:
```json
{
  "error": "Datos de entrada inválidos",
  "details": [
    {
      "field": "rnc",
      "message": "El RNC debe tener 9-11 dígitos"
    }
  ]
}
```

### Ejemplo 2: Listar Clientes con Paginación

**Request**:
```http
GET /api/clientes?page=2&pageSize=20&search=banco
Authorization: Bearer <token>
```

**Flujo**:
1. `authMiddleware` → Valida JWT
2. `roleMiddleware` → Verifica rol
3. `paginationMiddleware` → Parsea page=2, pageSize=20, offset=20
4. Controller → Query SQL con LIMIT 20 OFFSET 20
5. Response 200 con datos paginados

**Response**:
```json
{
  "data": [...],
  "total": 45,
  "page": 2,
  "pageSize": 20,
  "totalPages": 3
}
```

### Ejemplo 3: Error de Duplicado en BD

**Scenario**: Intentar crear cliente con código duplicado

## Decisiones Técnicas

### 1. Uso de Zod sobre Joi
- Mejor integración con TypeScript
- Type inference automático
- Más moderno y mantenido activamente
- Performance superior

### 2. Middlewares Separados
- `validateBody`, `validateParams`, `validateQuery` en lugar de un middleware único
- Mayor claridad en las rutas
- Permite aplicar solo lo necesario

### 3. Error Handler Global
- Un solo punto de manejo de errores
- Facilita debugging y logging
- Respuestas consistentes

### 4. Custom Error Classes
- Extienden Error nativo
- Incluyen `statusCode` para mapeo HTTP
- Facilitan testing con `instanceof`
