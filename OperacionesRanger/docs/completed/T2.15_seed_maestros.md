## Decisiones Técnicas Tomadas

### 1. Usar Map<codigo, id> para IDs dinámicos

**Decisión**: Trackear IDs insertados con Map en lugar de hardcodear.

**Justificación**:
- Los IDs AUTO_INCREMENT no se conocen de antemano
- Permite re-ejecución del script sin conflictos
- Facilita inserción de datos en orden correcto
- Garantiza relaciones FK correctas

**Alternativa descartada**: Hardcodear IDs (frágil, no funciona si se ejecuta múltiples veces)

---

### 2. INSERT IGNORE para manejo de duplicados

**Decisión**: Usar `INSERT IGNORE` en lugar de `INSERT` estándar.

**Justificación**:
- Permite re-ejecución del script sin errores
- Si datos ya existen, no falla - solo no inserta
- Facilita uso en desarrollo (no necesita limpieza manual)

**Manejo adicional**:
- Verificar `result.affectedRows > 0` para determinar si se insertó
- Si no se insertó, obtener ID con SELECT
- Mostrar mensaje diferente (⊗) para datos existentes

**Ejemplo**:
```typescript
const [result] = await pool.query(`INSERT IGNORE INTO clientes ...`);

if (result.affectedRows > 0) {
  // Insertado exitosamente
  id = result.insertId;
  console.log(`[SEED] ✓ Cliente: ${codigo} - ${nombre}`);
} else {
  // Ya existe, obtener ID
  const [rows] = await pool.query(`SELECT id FROM clientes WHERE codigo = ?`);
  id = rows[0].id;
  console.log(`[SEED] ⊗ Cliente: ${codigo} - ${nombre} (ya existe)`);
}
```

### 3. Readline para confirmación de limpieza

**Decisión**: Usar módulo `readline` de Node.js para solicitar confirmación.

**Justificación**:
- Previene eliminación accidental de datos
- UX clara: muestra advertencia y espera respuesta
- No requiere dependencias adicionales (built-in)

**Implementación**:
```typescript
function askConfirmation(question: string): Promise<boolean> {
  const rl = readline.createInterface({
    input: process.stdin,
    output: process.stdout,
  });

  return new Promise((resolve) => {
    rl.question(question, (answer) => {
      rl.close();
      resolve(answer.toLowerCase() === 's' || answer.toLowerCase() === 'y');
    });
  });
}
```

**Flujo**:
1. Detectar flag `--clean`
2. Mostrar advertencia
3. Solicitar confirmación (s/n)
4. Si 'n': cancelar (exit 0)
5. Si 's': ejecutar limpieza

## Problemas Encontrados y Soluciones

### Problema 1: Errores de compilación TypeScript (pool.query<>)

**Descripción**: TypeScript no aceptaba type arguments en `pool.query<ResultSetHeader>()`.

**Error**:
```
TS2347: Untyped function calls may not accept type arguments.
```

**Causa**: La firma de `pool.query` no acepta type arguments directamente.

**Solución**:
1. Envolver llamada en paréntesis: `(await pool.query(...))`
2. Agregar cast al final: `as [ResultSetHeader, any]`

**Antes**:
```typescript
const [result] = await pool.query<ResultSetHeader>(`INSERT ...`, params);
```

**Después**:
```typescript
const [result] = (await pool.query(`INSERT ...`, params)) as [ResultSetHeader, any];
```

**Tiempo invertido**: 25 minutos (12 ocurrencias corregidas)

---

### Problema 2: Campo RUC vs RNC en tabla clientes

**Descripción**: Script usaba campo `ruc` pero tabla tiene `rnc`.

**Error**:
```
[SEED] ✗ Error insertando cliente BPD001: Unknown column 'ruc' in 'field list'
```

**Causa**: Asunción incorrecta sobre nombre de campo (usé `ruc` común en Perú, pero en RD es `rnc`).

**Solución**:
1. Ejecutar `DESCRIBE clientes` para ver estructura real
2. Corregir interface: `ruc: string` → `rnc: string`
3. Corregir query: `(codigo, nombre, ruc, ...)` → `(codigo, nombre, rnc, ...)`
4. Corregir datos: `ruc: "..."` → `rnc: "..."`

**Aprendizaje**: Verificar estructura de BD antes de codear.

**Tiempo invertido**: 10 minutos

## Próximos Pasos / Recomendaciones

### 1. Agregar transacciones para atomicidad

**Recomendación**: Envolver inserción en transacción para garantizar atomicidad.

**Implementación sugerida**:
```typescript
const connection = await pool.getConnection();
await connection.beginTransaction();

try {
  const clienteIds = await insertClientes(connection, clientes);
  const ubicacionIds = await insertUbicaciones(connection, ubicaciones, clienteIds);
  const puestoIds = await insertPuestos(connection, puestos, ubicacionIds);
  await insertIncentivos(connection, incentivos, puestoIds);

  await connection.commit();
} catch (error) {
  await connection.rollback();
  throw error;
} finally {
  connection.release();
}
```

**Beneficio**: Si una inserción falla, se revierten todas las anteriores (all-or-nothing).

**Prioridad**: Media (mejora de calidad, no bloqueante)

### Valor hora de incentivos

**Cálculo**:
- 1 quincena = 15 días
- 1 día = 24 horas
- 15 días × 24 horas = 360 horas

**Fórmula**: `valor_hora = monto / 360`

**Ejemplos**:
- Incentivo RD$3,600 → RD$10/hora
- Incentivo RD$5,400 → RD$15/hora
- Incentivo RD$1,800 → RD$5/hora

**Nota**: El campo `valor_hora` es GENERATED STORED en BD, se calcula automáticamente.
