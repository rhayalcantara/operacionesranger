### Flujo de Carga de Datos

1. **Componente inicializa** (`ngOnInit`)
2. **Calcula fechas** del mes actual (primer y último día)
3. **Llama en paralelo** a 3 servicios:
   - `turnosService.getAll(fechaInicio, fechaFin)` → Turnos del mes
   - `rrhhService.getGuardianes(status: 1)` → Guardianes activos
   - `turnosService.getAll(procesado_nomina: false)` → Pendientes
4. **Actualiza estado** con respuestas (o muestra errores)
5. **Calcula horas totales** sumando horas_normales + horas_extras

### Manejo de Errores

Cada llamada HTTP tiene manejo de errores:

```typescript
.subscribe({
  next: (response) => {
    // Actualizar datos
    this.isLoading = false;
  },
  error: (error) => {
    console.error('Error:', error);
    this.errorMessage = 'Mensaje amigable';
    this.isLoading = false;
    // Mostrar datos de ejemplo (0) si endpoint no existe
  }
});
```

**Estrategia**: Si el backend no tiene endpoints implementados aún, muestra valores en 0 en lugar de bloquear la UI.

## Problemas Encontrados y Soluciones

### Problema 1: Advertencia de Budget

**Síntoma**: Bundle inicial excede 500 kB (735.28 kB)

**Causa**:
- Angular Material (módulos grandes)
- Angular core
- Múltiples servicios HTTP

**Solución aplicada**:
- Usar standalone components (reduce bundle)
- Lazy loading de rutas (dashboard se carga bajo demanda)
- Solo importar módulos Material necesarios

**Solución futura**:
- Implementar lazy loading de Material modules
- Considerar Material v3 (componentes más ligeros)
- Tree-shaking agresivo en producción

### Problema 2: Estilos del Dashboard Exceden Budget

**Síntoma**: Component styles 4.36 kB (límite 4 kB)

**Causa**:
- Gradientes CSS complejos
- Media queries responsive
- Estilos de animaciones

**Solución aplicada**:
- Mantener estilos en component scope (mejor que global)
- CSS optimizado con selectores eficientes

**Solución futura**:
- Extraer estilos comunes a theme SCSS
- Usar CSS variables para gradients

### Problema 3: Endpoints Backend No Implementados

**Síntoma**: Algunos endpoints de turnos no existen aún

**Causa**:
- Frontend avanzó antes que backend (Fase 2 al 67.9%)
- Endpoints de turnos son Módulo 4 (pendiente)

**Solución aplicada**:
- Manejo de errores robusto
- Mostrar valores en 0 si endpoint falla
- Logging de errores en consola para debugging

**Resultado**: Dashboard funcional incluso sin backend completo

## Lecciones Aprendidas

1. **Standalone components simplifica arquitectura**: No necesitar NgModule reduce boilerplate
2. **Servicios robustos desde el inicio**: Implementar interfaces TypeScript completas evita refactoring posterior
3. **Error handling es crítico**: Dashboard debe funcionar incluso sin backend completo
4. **CSS Grid > Flexbox para layouts complejos**: Grid más declarativo para responsive design
5. **Material Design tiene costo**: Bundle grande pero UX consistente
6. **Loading states mejoran percepción**: Spinners hacen que la app se sienta más rápida
