##### Selectores Jerárquicos (Cascading)

**Flujo implementado:**
1. **Cliente** → Habilita Ubicaciones (filtradas por cliente_id)
2. **Ubicación** → Habilita Puestos (filtrados por ubicacion_id)
3. Reseteo automático de campos dependientes al cambiar superior

**Implementación técnica:**
```typescript
// Cliente → Ubicación
this.turnoForm.get('cliente_id_selector')?.valueChanges
  .pipe(takeUntil(this.destroy$))
  .subscribe((clienteId) => {
    // Reset cascading fields
    this.turnoForm.patchValue({
      ubicacion_id_selector: null,
      puesto_id: null
    });
    // Load ubicaciones
    if (clienteId) {
      this.cargarUbicacionesPorCliente(clienteId);
    }
  });
```

##### Cálculo Automático de Horas

**Implementación:**
```typescript
combineLatest([
  this.turnoForm.get('hora_entrada')!.valueChanges,
  this.turnoForm.get('hora_salida')!.valueChanges
])
  .pipe(takeUntil(this.destroy$), debounceTime(500))
  .subscribe(([entrada, salida]) => {
    if (entrada && salida) {
      const horasCalculadas = this.turnosService.calcularHorasNormales(entrada, salida);
      this.turnoForm.patchValue({ horas_normales: horasCalculadas }, { emitEvent: false });
    }
  });
```

**Características:**
- ✅ Soporte para turnos nocturnos (overnight, e.g., 22:00 → 06:00)
- ✅ Debounce de 500ms
- ✅ Precisión de 2 decimales
- ✅ Conversión automática de minutos a horas

## Decisiones Técnicas

### 1. Formulario Reactivo vs Template-Driven

**Decisión:** Reactive Forms
**Justificación:**
- Mayor control sobre validaciones complejas
- Soporte nativo para validadores asíncronos
- Mejor testing
- Sigue patrones del resto del proyecto

### 2. Dialog vs Página Separada

**Decisión:** Dialog (MatDialog)
**Justificación:**
- Consistencia con otros módulos (clientes, ubicaciones, etc.)
- Mejor UX: el usuario mantiene contexto de la lista
- Menos overhead de navegación
- Soporte para ruta `/turnos/nuevo` que abre dialog automáticamente

### 3. Autocomplete vs Select para Guardianes

**Decisión:** Autocomplete con búsqueda remota
**Justificación:**
- 515 guardianes activos: demasiados para un select
- Búsqueda flexible por nombre/apellido/cédula
- Debounce evita sobrecarga al backend
- Mejor UX para selección rápida

### 4. Cálculo de Horas: Frontend vs Backend

**Decisión:** Cálculo en frontend + validación en backend
**Justificación:**
- Feedback inmediato al usuario (auto-complete)
- Backend valida en stored procedure `sp_registrar_turno`
- Redundancia para seguridad (defense in depth)

### 5. Campos Auto-Calculados (tipo_turno, es_feriado)

**Decisión:** Solo backend
**Justificación:**
- Lógica de negocio crítica (debe ser single source of truth)
- Depende de configuración (tabla `configuracion_turnos`, `feriados`)
- Stored procedure `sp_registrar_turno` los calcula
- Frontend solo muestra resultados

### 6. Validación de Duplicados

**Decisión:** Async validator con debounce
**Justificación:**
- Validación en tiempo real sin submit
- Debounce (500ms) reduce llamadas al backend
- Backend verifica en DB (constraint `uk_empleado_puesto_fecha`)
- Mejor UX: error visible antes de submit

## Integración con Backend

### Flujo de Creación de Turno

1. **Frontend** llama a `POST /api/turnos` con datos:
   ```typescript
   {
     empleado_id: 1001,
     puesto_id: 42,
     fecha: "2026-01-20",
     hora_entrada: "06:00:00",
     hora_salida: "18:00:00",
     horas_normales: 12,
     horas_extras: 0,
     observaciones: "..."
   }
   ```

2. **Backend** ejecuta stored procedure `sp_registrar_turno`:
   - Valida empleado existe y está activo
   - Valida puesto existe y está activo
   - Verifica no hay duplicado
   - Calcula `tipo_turno` (DIURNO/NOCTURNO) basado en `hora_entrada`
   - Verifica `es_feriado` consultando tabla `feriados`
   - Calcula incentivo si aplica
   - Inserta registro

3. **Backend** retorna turno creado con campos auto-calculados:
   ```typescript
   {
     id: 1234,
     empleado_id: 1001,
     puesto_id: 42,
     fecha: "2026-01-20",
     hora_entrada: "06:00:00",
     hora_salida: "18:00:00",
     horas_normales: 12,
     horas_extras: 0,
     tipo_turno: "DIURNO",        // ✅ Auto-calculado
     es_feriado: false,            // ✅ Auto-calculado
     tipo_feriado: null,           // ✅ Auto-calculado
     procesado_nomina: false,
     observaciones: "...",
     created_at: "2026-01-19T16:30:00Z",
     empleado: { ... },            // ✅ Joined data
     puesto: { ... }               // ✅ Joined data
   }
   ```

4. **Frontend** muestra pantalla de resultado con campos destacados
