## Componentes Creados

### 1. TurnosListComponent

**Ubicación:** `frontend/src/app/modules/turnos/turnos-list/`

**Responsabilidades:**
- Mostrar tabla paginada de turnos
- Filtros avanzados (7 filtros diferentes)
- Búsqueda general por guardián
- Acciones CRUD con validación de permisos
- Gestión de estado de carga
- Paginación server-side

**Columnas de la Tabla:**

| Columna | Descripción | Formato |
|---------|-------------|---------|
| Fecha | Fecha del turno | dd/MM/yyyy |
| Guardián | Nombre y cédula del empleado | Nombre + Cédula |
| Puesto | Nombre del puesto con tooltip | Texto + Tooltip |
| Horario | Hora entrada → Hora salida | HH:mm → HH:mm |
| Horas Normales | Cantidad de horas normales | X.XX hrs |
| Horas Extras | Cantidad de horas extras | X.XX hrs |
| Total Horas | Suma de normales + extras | X.XX hrs |
| Tipo Turno | Badge con icono | 🌞 DIURNO / 🌙 NOCTURNO |
| Feriado | Badge si es feriado | 🎉 FERIADO |
| Procesado | Estado de procesamiento | ✅ PROCESADO / ⏳ PENDIENTE |
| Acciones | Botones de acción | Ver / Editar / Eliminar |

**Filtros Implementados:**

1. **Búsqueda General**
   - Input de texto
   - Busca por nombre o cédula de guardián
   - Debounce de 500ms
   - Backend: parámetro `search`

2. **Panel de Filtros Avanzados** (mat-expansion-panel)
   - **Fecha Inicio:** mat-datepicker
   - **Fecha Fin:** mat-datepicker
   - **Tipo Turno:** mat-select (Todos, DIURNO, NOCTURNO)
   - **Solo Feriados:** mat-checkbox
   - **Solo Procesados:** mat-checkbox
   - **Botón "Aplicar Filtros"**
   - **Botón "Limpiar Filtros"**

**Paginación:**
- Server-side con mat-paginator
- Page size options: [10, 25, 50, 100]
- Default page size: 25
- Total count desde backend
- Botones first/last habilitados

**Permisos por Rol:**

| Acción | ADMIN | SUPERVISOR | CONSULTA |
|--------|-------|------------|----------|
| Ver lista | ✅ | ✅ | ✅ |
| Ver detalles | ✅ | ✅ | ✅ |
| Crear turno | ✅ | ✅ | ❌ |
| Editar turno | ✅ | ✅ | ❌ |
| Eliminar turno | ✅ | ❌ | ❌ |

**Restricciones:**
- No se puede editar turno procesado (procesado_nomina = true)
- No se puede eliminar turno procesado
- Botón FAB solo visible para ADMIN y SUPERVISOR
- Botón "Editar" deshabilitado si procesado o sin permisos
- Botón "Eliminar" deshabilitado si procesado o sin permisos

## Endpoints Utilizados

### GET /api/turnos
**Descripción:** Obtener lista de turnos con filtros
**Parámetros:**
- `page` (number): Número de página (1-indexed)
- `pageSize` (number): Tamaño de página
- `search` (string): Búsqueda general
- `fecha_inicio` (string): Fecha inicio (YYYY-MM-DD)
- `fecha_fin` (string): Fecha fin (YYYY-MM-DD)
- `empleado_id` (number): ID del guardián
- `puesto_id` (number): ID del puesto
- `tipo_turno` (string): 'DIURNO' o 'NOCTURNO'
- `es_feriado` (boolean): true para solo feriados
- `procesado_nomina` (boolean): true para solo procesados

**Respuesta:**
```typescript
{
  data: Turno[],
  total: number,
  page: number,
  pageSize: number,
  totalPages: number
}
```

### GET /api/turnos/:id
**Descripción:** Obtener detalles de un turno específico
**Respuesta:** `Turno` completo con datos joined

### PUT /api/turnos/:id
**Descripción:** Actualizar un turno existente
**Body:** `Partial<TurnoCreateRequest>`
**Respuesta:** `Turno` actualizado

### DELETE /api/turnos/:id
**Descripción:** Eliminar un turno
**Respuesta:** `void`

## Flujos de Usuario

### 1. Ver Lista de Turnos
1. Usuario accede a `/turnos`
2. Sistema carga primera página (25 items)
3. Usuario ve tabla con turnos
4. Usuario puede cambiar página o tamaño de página

### 2. Buscar por Guardián
1. Usuario escribe en campo de búsqueda
2. Sistema espera 500ms (debounce)
3. Sistema ejecuta búsqueda en backend
4. Tabla se actualiza con resultados

### 3. Aplicar Filtros Avanzados
1. Usuario abre panel de filtros (click en header)
2. Usuario selecciona filtros deseados
3. Usuario click en "Aplicar Filtros"
4. Sistema reset a página 1
5. Sistema carga datos con filtros
6. Tabla se actualiza

### 4. Ver Detalles de Turno
1. Usuario click en botón "Ver" (ojo)
2. Sistema abre TurnoDetalleDialogComponent
3. Usuario ve toda la información readonly
4. Usuario cierra dialog

### 5. Editar Turno
1. Usuario click en botón "Editar" (lápiz)
2. Sistema valida: permisos + no procesado
3. Sistema abre TurnoFormComponent en modo edición
4. Usuario edita campos
5. Usuario guarda
6. Sistema actualiza backend
7. Sistema muestra mensaje de éxito
8. Tabla se recarga automáticamente

### 6. Eliminar Turno
1. Usuario click en botón "Eliminar" (papelera)
2. Sistema valida: permisos + no procesado
3. Sistema abre ConfirmDialogComponent
4. Usuario confirma eliminación
5. Sistema elimina en backend
6. Sistema muestra mensaje de éxito
7. Tabla se recarga automáticamente

### 7. Crear Nuevo Turno
1. Usuario click en botón FAB (bottom-right)
2. Sistema abre TurnoFormComponent vacío
3. Usuario completa formulario
4. Usuario guarda
5. Sistema crea en backend
6. Sistema muestra mensaje de éxito
7. Tabla se recarga automáticamente

## Decisiones Técnicas

### 1. Server-Side Pagination
**Decisión:** Implementar paginación en backend
**Razón:** Escalabilidad - pueden existir miles de turnos
**Implementación:** Backend retorna `{ data, total }`, frontend usa mat-paginator

### 2. Debounce en Búsqueda
**Decisión:** 500ms de debounce
**Razón:** Evitar llamadas innecesarias al escribir rápido
**Implementación:** RxJS `debounceTime(500)` en searchSubject

### 3. Filtros en Panel Expandible
**Decisión:** mat-expansion-panel para filtros
**Razón:** No sobrecargar UI, opcional para usuarios
**Estado Inicial:** Cerrado (panelOpenState = false)

### 4. Badges con Emojis
**Decisión:** Usar emojis en badges
**Razón:** Rápida identificación visual, sin necesidad de iconos adicionales
**Emojis:** 🌞 (día), 🌙 (noche), 🎉 (feriado), ✅ (procesado), ⏳ (pendiente)

### 5. FAB Button vs Header Button
**Decisión:** Botón FAB flotante en lugar de botón en header
**Razón:** Acceso rápido desde cualquier posición del scroll
**Posición:** bottom-right con z-index alto

### 6. Dialog para Detalles
**Decisión:** Dialog en lugar de ruta separada
**Razón:** Contexto rápido sin salir de la lista
**Alternativa:** También se puede implementar ruta `/turnos/:id`

### 7. Confirmación de Eliminación
**Decisión:** Dialog de confirmación obligatorio
**Razón:** Prevenir eliminaciones accidentales (no hay undo)
**Componente:** ConfirmDialogComponent reutilizable
